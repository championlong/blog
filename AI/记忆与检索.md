# 智能体记忆

## 智能体问题

1. 无状态导致的对话遗忘： 上下文丢失、个性化缺失、学习能力受限、一致性问题
2. 模型内置知识的局限性： 知识时效性、 专业领域知识、 事实准确性、 可解释性

## 记忆系统

人类记忆的几个阶段类比：

1. 编码：将感知到的信息转换为可存储的形式。

2. 存储：将编码后的信息保存在记忆系统中

3. 检索：根据需要从记忆中提取相关信息

4. 整合：将短期记忆转化为长期记忆

5. 遗忘：删除不重要或过时的信息

# RAG

检索增强生成（Retrieval-Augmented Generation，RAG）主要分为两大核心环节:

1. 数据准备阶段：系统通过数据提取、文本分割和向量化，将外部知识构建成一个可检索的数据库。
   1. 多模态文档载入：无论输入是PDF、Word、Excel、图片还是音频，最终都会转换为标准的Markdown格式，然后进入统一的分块、向量化和存储流程
   2. 智能分块策略：系统可以利用Markdown的标题结构（#、##、###等）进行精确的语义分割。并且根据Token数量进行智能分块。
   3. 统一嵌入与向量存储：它负责将文本转换为高维向量，使得计算机能够理解和比较文本的语义相似性。
2. 应用阶段：系统会响应用户的提问，从数据库中检索相关信息，将其注入Prompt，并最终驱动大语言模型生成答案。 高级检索策略如下：
   1. 多查询扩展：通过生成语义等价的多样化查询来提高检索召回率的技术。
   2. 假设文档嵌入：通过让LLM先生成一个假设性的答案段落，然后用这个答案段落去检索真实文档，从而缩小了查询和文档之间的语义鸿沟
   3. 扩展检索框架：扩展-检索-合并

# 上下文工程

提示词工程：关注如何编写与组织有效的 LLM的指令以获得更优结果

上下文工程：在推理阶段，如何策划与维护最优的信息集合。不仅包含提示本身，还包含其他会进入上下文窗口的一切信息。上下文必须被视作一种有限资源，且具有边际收益递减。

**过多上下文的问题：**

上下文腐蚀：随着上下文窗口中的 tokens 增加，模型从上下文中准确回忆信息的能力反而下降。Transformer 让每个 token 能够与上下文中的所有 token 建立关联，理论上形成 级别的两两注意力关系。随着上下文长度增长，模型对这些两两关系的建模能力会被“拉薄”，从而自然地产生“上下文规模”与“注意力集中度”的张力。

## 建设上下文工程手段

用尽可能少、但高信号密度的tokens，最大化获得期望结果的概率。

* **压缩整合（Compaction）：**当对话接近上下文上限时，对其进行高保真总结，并用该摘要重启一个新的上下文窗口，以维持长程连贯性。
* **结构化笔记（Structured note-taking）：**智能体以固定频率将关键信息写入**上下文外的持久化存储**，在后续阶段按需拉回。
* **子代理架构（Sub-agent architectures）：**由主代理负责高层规划与综合，多个专长子代理在“干净的上下文窗口”中各自深挖、调用工具并探索，最后仅回传**凝练摘要**

上下文管理接口的四个阶段示例：

1. Gather多源信息汇集：添加系统指令、从记忆系统检索相关记忆 、从 RAG 系统检索相关知识 、添加对话历史、添加自定义信息包等
2. Select智能信息选择：分离系统指令和其他信息、计算系统指令占用的 token、为其他信息计算综合分数（计算相关性、新近性、数过滤低质量信息）、按分数降序排序、贪心选择按分数从高到低填充
3. Structure结构化输出：将选中的信息组织成结构化的上下文模板
4. Compress兜底压缩：对超限上下文进行压缩处理。

# 通信协议

通信协议带来的改变是根本性的：

1. **标准化接口**让不同服务提供统一的访问方式。
2. **互操作性**使得不同开发者的工具可以无缝集成。
3. **动态发现**允许智能体在运行时发现新的服务和能力。
4. **可扩展性**让系统能够轻松添加新的功能模块。

## MCP

MCP（Model Context Protocol）由 Anthropic 团队提出，理念是标准化智能体与外部工具资源的通信方式。它允许智能体和工具之间共享丰富的上下文信息。

### MCP 协议三层架构设计

1. Host：Host 是用户直接交互的界面，它管理整个对话流程。
2. Client：Client负责与适当的 MCP Server 建立连接，发送请求并接收响应。
3. Servers：MCP Server 被调用，执行实际逻辑

### MCP调用流程

1. **工具发现阶段**：MCP Client 连接到 Server 后，首先调用 list_tools() 获取所有可用工具的描述信息（包括工具名称、功能说明、参数定义）
2. **上下文构建**：Client 将工具列表转换为 LLM 能理解的格式，添加到系统提示词中。
3. **模型推理**：LLM 分析用户问题和可用工具，决定是否需要调用工具以及调用哪个工具。这个决策基于工具的描述和当前对话上下文。
4. **工具执行**：如果 LLM 决定使用工具，Client 通过 MCP Server 执行所选工具，获取结果
5. **结果整合**：工具执行结果被送回给 LLM，LLM 结合结果生成最终回答

### 与Function Calling差异

`Function Calling` 是大语言模型的一项核心能力，它体现了模型内在的智能，使模型能够理解何时需要调用函数，并精准生成相应的调用参数。

`MCP` 则扮演着基础设施协议的角色，它在工程层面解决了工具与模型如何连接的问题，通过标准化的方式来描述和调用工具

### MCP传输方式

1.  Memory Transport - 内存传输：使用内置服务。适用单元测试、快速原型开发
   ```python
   from hello_agents.tools import MCPTool
   
   # 使用内置演示服务器（Memory传输）
   mcp_tool = MCPTool()
   
   # 列出可用工具
   result = mcp_tool.run({"action": "list_tools"})
   print(result)
   
   # 调用工具
   result = mcp_tool.run({
       "action": "call_tool",
       "tool_name": "add",
       "arguments": {"a": 10, "b": 20}
   })
   print(result)
   ```

   

2. Stdio Transport - 标准输入输出传输：可以使用自定义Python服务器或社区服务器。适用本地开发、调试、Python 脚本服务器
   ```python
   from hello_agents.tools import MCPTool
   
   # 方式1：使用自定义Python服务器
   mcp_tool = MCPTool(server_command=["python", "my_mcp_server.py"])
   
   # 方式2：使用社区服务器（文件系统）
   mcp_tool = MCPTool(server_command=["npx", "-y", "@modelcontextprotocol/server-filesystem", "."])
   
   # 列出工具
   result = mcp_tool.run({"action": "list_tools"})
   print(result)
   
   # 调用工具
   result = mcp_tool.run({
       "action": "call_tool",
       "tool_name": "read_file",
       "arguments": {"path": "README.md"}
   })
   print(result)
   ```

3. HTTP Transport - HTTP 传输：连接到远程 HTTP MCP 服务器。适用生产环境、远程服务、微服务架构
   ```python
   async def test_http_transport():
       # 连接到远程 HTTP MCP 服务器
       client = MCPClient("http://api.example.com/mcp")
   
       async with client:
           # 获取服务器信息
           tools = await client.list_tools()
           print(f"远程服务器工具: {len(tools)} 个")
   
           # 调用远程工具
           result = await client.call_tool("process_data", {
               "data": "Hello, World!",
               "operation": "uppercase"
           })
           print(f"远程处理结果: {result}")
   ```

4. SSE Transport - Server-Sent Events传输：连接到 SSE MCP 服务器 。适用实时通信、流式处理、长连接
   ```python
   async def test_sse_transport():
       # 连接到 SSE MCP 服务器
       client = MCPClient(
           "http://localhost:8080/sse",
           transport_type="sse"
       )
   
       async with client:
           # SSE 特别适合流式处理
           result = await client.call_tool("stream_process", {
               "input": "大量数据处理请求",
               "stream": True
           })
           print(f"流式处理结果: {result}")
   ```

5. StreamableHTTP Transport -流式 HTTP 传输：连接到 StreamableHTTP MCP 服务器。适用需要双向流式通信的 HTTP 场景
   ```python
   async def test_streamable_http_transport():
       # 连接到 StreamableHTTP MCP 服务器
       client = MCPClient(
           "http://localhost:8080/mcp",
           transport_type="streamable_http"
       )
   
       async with client:
           # 支持双向流式通信
           tools = await client.list_tools()
           print(f"StreamableHTTP 服务器工具: {len(tools)} 个")
   ```

## A2A

A2A（Agent-to-Agent Protocol）协议由 Google 团队提出。理念是实现智能体之间的点对点（P2P）通信。



## ANP

ANP（Agent Network Protocol）是一个概念性的协议框架由开源社区维护，理念是构建大规模智能体网络的基础设施。ANP 的设计目标就是提供一套标准化的机制，来解决**服务发现**、**路由选择**和**网络扩展性**问题。
